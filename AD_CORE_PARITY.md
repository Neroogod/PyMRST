## Status policy

- `ported`: a snake-case filename counterpart exists, and if the MRST file is a classdef with >= 5 methods, at least 60% of them (excluding pinned platform/layout/subsref cases) are present in that counterpart.
- `ported-consolidated`: the MATLAB symbol is explicitly referenced inside a consolidated Python module.
- `ported-shallow`: a counterpart exists but scores below the depth bar; `methods_absent` names what is missing.
- `wrapper`: a counterpart exists and implements none of the scored methods.
- `validated-reference`: a test or validation script explicitly names the MATLAB symbol or its Python snake-case spelling. This does not yet grade validation depth.
- `excluded-catalog`: MATLAB `Contents.m` catalog only.
- `excluded-platform`: MATLAB MEX build/runtime source; its numerical fallback must still be ported and validated.
- `excluded-external`: optional external repository/data integration, outside the self-contained numerical core.
- `excluded-deprecated`: MRST explicitly deprecated the implementation; its active replacement behavior is provided by the facility layer.
- `excluded-external-solver`: wrapper requiring an optional external binary solver; PyMRST's native CPR/direct solvers remain available.
- `excluded-visualization`: MATLAB graphics-only helper.
- `excluded-benchmark-driver`: MATLAB timing/plot orchestration whose reusable benchmark kernel is ported and validated.
- `pending-review`: no defensible automatic mapping; requires manual classification or implementation.
